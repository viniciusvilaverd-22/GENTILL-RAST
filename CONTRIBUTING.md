# Contributing

O REST Gentill é publicado para transparência técnica, avaliação e documentação. Contribuições externas não são aceitas automaticamente.

## Pull requests

Pull requests públicos devem ser previamente combinados com a equipe responsável pelo projeto. PRs não solicitados podem ser encerrados sem revisão detalhada.

## Regras técnicas

Mudanças aceitas devem:

- preservar contratos existentes ou documentar formalmente a evolução;
- incluir testes compatíveis com o componente alterado;
- não incluir credenciais, dumps, chaves, tokens ou arquivos locais;
- manter separação entre patrimônio, identidade e telemetria;
- preservar compatibilidade dos identificadores internos históricos quando necessário;
- atualizar ADRs quando a mudança alterar decisões arquiteturais;
- passar pelos builds e validações aplicáveis.

## Segurança

Vulnerabilidades não devem ser relatadas por issue pública. Consulte [SECURITY.md](SECURITY.md).

## Licença de contribuições

Nenhuma contribuição externa deve ser enviada sem concordância prévia sobre os termos de propriedade intelectual aplicáveis ao projeto.
